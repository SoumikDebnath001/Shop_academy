Admin panel

- New address: http://localhost:3000/grassroots-admin, with the login at /grassroots-admin/login. The old /admin now shows "not found", and the store no longer links to the admin panel anywhere.
- Login steps:
  a. Email and password.
  b. A 6-digit code sent by email. It expires in 5 minutes and allows 5 tries.
  c. A Google Authenticator code. On an admin's first login they scan a QR code to set it up, and a code can't be reused.
- Session:
  - The session is kept in a secure browser cookie that page scripts can't read, instead of in the browser's local storage.
  - It lasts 4 hours, and a new login signs out any older session.
  - Signing out makes the old cookie useless, even if someone copied it.
- Brute-force protection: the account locks for 15 minutes after 5 failed attempts. Each IP address is also limited to 20 login requests per 15 minutes.
- Creating admins: the first admin needs a setup key from .env. After that, only a signed-in superadmin can add admins, and new passwords need at least 12 characters with mixed character types.

What you need to do

1. Your current admins must sign in again at the new URL and set up Google Authenticator on that first login.
2. Email is not configured yet. While NODE_ENV isn't production, the login code is printed in the backend terminal. In production, login fails until you fill in the SMTP_* lines I added to Backend/.env.
3. I added two secret keys to Backend/.env: ADMIN_JWT_SECRET and ADMIN_2FA_ENCRYPTION_KEY. Don't change the encryption key later, or every admin will have to set up Google Authenticator again.
4. Lost phone: there are no recovery codes. To reset an admin, clear totpEnabled and totpSecret on their record in the database.
5. Placeholder email: the support email on the profile page is now support@obuyagrassroots.com. Replace it with your real address.
6. Deploying: keep the store and the API on the same main domain (for example shop.x.com and api.x.com) and use HTTPS, or the admin cookie won't be sent.
